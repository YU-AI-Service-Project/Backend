2026-11-25에 `main`의 `1f9f2dc`를 기준으로 요청이 Spring Boot에 들어오는 시점부터 인증·DB·외부 서비스 호출까지 검토했다. 일반 사용자가 공개 조회와 회원 API를 이용하고, 내부 운영 API는 별도 인증과 허용 IP로 구성하는 환경을 기준으로 삼았다.

## 배포 환경에서 확인할 사항

- 공개 프록시에서 `/internal/**`을 차단하고 운영 경로는 내부 접속으로 분리한다. 핸들러는 연결 IP와 읽기·쓰기 토큰을 함께 검사한다. 공개 프록시에서 인증 요청률을 제어할 때는 신뢰된 연결에서 정한 실제 클라이언트 주소를 사용한다.
- 카카오 호출을 사용하는 위치 검색·ETA·추천에는 공급자 쿼터에 맞는 요청률과 전체 예산을 배포 환경에서 설정한다. 현재 애플리케이션의 병렬 호출 상한과 KECO의 일일 상한은 유지한다. 명목상의 공급자 한도는 실제 테스트 키와 인프라에서 확인한다.
- 이메일 로그인은 제출 이메일별 제한을 사용한다. 분산 로그인 시도 제한과 정상 사용자의 잠금 방지를 함께 검증해야 한다. Google 연결 해제는 WattUp의 연결을 제거한다. 공급자에서 이미 발급된 토큰의 철회와 최근 인증 여부 확인은 실제 OAuth 정책으로 검증한다.
- 운영 프록시의 TLS, 비밀키 값과 권한, 실제 OAuth·SMTP 공급자 설정과 공개 배포는 이번 점검에 포함되지 않았다.
